# Socket.IO API

Messages exchanged between the client and the server, over a TLS WebSocket.

Every server handler ignores requests from sockets that are not logged in (except `login` and `register`), checks that the user is a member of the room it acts on, and validates its arguments. When a request is refused, the server answers with `error_message`.

Notation: `roomId` is an integer, `b64` a base64 string, `hex` a hex string.

## Messages handled by the server

### `register`

    { name: string, password: hex, publicKey: string, encryptedPrivateKey: {iv, authTag, salt, data} }

Creates an account and logs it in. `name` is 3-20 letters, digits or `_`. `password` is not the password: it is `PBKDF2(password, "e2e-chat-auth:" + name)`, 64 hex chars. `publicKey` is the user's RSA-2048 public key (PEM), `encryptedPrivateKey` the matching private key encrypted with AES-256-GCM under a key derived from the password with a random salt.

Answers `register_ok` (same content as `login_ok`, without keys) or `register_error`.

### `login`

    { name: string, password: hex }

Logs in with the derived secret described above. After 5 failed attempts the username is locked for one minute.

Answers `login_ok` or `login_error`. If a channel the user is in still needs a key rotation, the server also sends `rekey_request`.

### `new message`

    { room: roomId, content: string }                                  // public channel
    { room: roomId, iv: hex, authTag: hex, ciphertext: b64, keyVersion }  // private channel
    { room: roomId, iv: hex, authTag: hex, ciphertext: b64, keys }        // direct message

Posts a message to a room the user is a member of. Private channels and direct messages only accept ciphertext:
- private channel: `keyVersion` must be the current version of the channel key,
- direct message: `keys` maps each of the two members to the message key encrypted with their RSA public key.

### `request_direct_room`

    { to: username }

Opens (or creates) the direct room with another user. Sends `update_room` to both users.

### `add_channel`

    { name: string, description: string, private: boolean, encryptedRoomKey: b64 }

Creates a channel with the current user as only member. `name` is 1-30 letters, digits, `-` or `_`. A private channel needs `encryptedRoomKey`: the channel key, generated by the client and encrypted with the creator's public key. Sends `update_room` to the creator, and `update_public_channels` to everyone for a public channel.

### `join_channel`

    { id: roomId }

Joins a public channel. Sends `update_room`.

### `add_user_to_channel`

    { user: username, channel: roomId, encryptedRoomKey: b64 }

Adds a user to a channel the current user is a member of. For a private channel, `encryptedRoomKey` is the current channel key encrypted with the added user's public key. Sends `update_room` and `room_key_update` to the added user.

### `leave_channel`

    { id: roomId }

Leaves a channel (not the default ones). Sends `remove_room`. For a private channel, the key of the user who left is deleted, the remaining members get `channel_rekeying`, and one of them gets `rekey_request`.

### `rotate_room_key`

    { roomId, version: integer, keys: { username: b64 } }

Answer to `rekey_request`: a new channel key, encrypted for every current member and no one else. `version` must be the current version + 1. Every member gets `room_key_update`.

## Messages handled by the client

### `login_ok`

    { users: [{username, active, publicKey}], rooms: [room], publicChannels: [room],
      encryptedPrivateKey, roomKeys: { roomId: { version: b64 } } }

Users with their public keys, the rooms of the user (with history), the public channels, the encrypted private key and every version of the user's channel keys, so old messages can still be decrypted.

### `new message`

    { username, room: roomId, time, direct: boolean, ...message fields }

A new message in one of the user's rooms.

### `user_state_change`

    { username, active: boolean, publicKey }

Another user went online or offline.

### `update_room`

    { room, moveto: boolean }

A room was created or changed. With `moveto` the client switches to it.

### `update_user`

    { room: roomId, username, action: 'added' | 'removed', members: [username] }

The members of a room changed.

### `update_public_channels`

    { publicChannels: [room] }

A public channel was created.

### `remove_room`

    { room: roomId }

The user left a room.

### `channel_rekeying`

    { roomId }

A member left this private channel. The client stops sending messages to it until it gets the new key.

### `rekey_request`

    { roomId, version, members: [username] }

The client generates a new channel key, encrypts it for each of `members` and answers with `rotate_room_key`.

### `room_key_update`

    { roomId, version, encryptedKey: b64 }

A channel key, encrypted with the user's public key.

### `error_message`

    { message: string }

A request was refused.
